Linkclump Plus: Protocol Filtering & URL Scheme Test

Return to Test Page Index

About

This test page systematically verifies how Linkclump Plus handles various URL schemes, relative paths, and protocol boundaries. It validates both the selection filtering in the content script and the tab creation behavior in the background script.

Core Specification / Boundary Principle:
  • Content Script Filter (lifecycle.ts): Link selection explicitly rejects only two patterns:
    • Links matching the regular expression /^javascript:/i.
    • Links with empty href attribute or href="#".
  • URL Resolution: Relative paths (./, /) and protocol-relative URLs (//) are automatically resolved by the browser's DOM (a.href property) to fully qualified absolute URLs before being passed to Linkclump Plus.
  • Background Protection (openTab.ts): When attempting to open privileged or restricted schemes (such as chrome://settings/, about:preferences, or about:config), browser security policies reject the API call. Linkclump Plus wraps these calls inside safeAsync, safely catching errors without crashing the background worker or halting subsequent tabs in the queue.
  • Adversarial Safety Precautions: All external Web URLs use RFC 2606 reserved domains (example.com, example.org) with rel="noopener noreferrer". External application schemes (mailto:) are strictly limited in count and equipped with an interactive interceptor. Data URIs use benign text/plain only.

Procedure & Expected Results

Hold the configured key, then press and drag the mouse button across the target link group. Release the button to trigger the configured action (e.g. "Opened as New Tabs" or "Copied to Clipboard").

Test Cases

Case 1: Standard Web Protocols (http://, https://)

HTTP HTTPS Expect: Selected & Opened

Standard external web URLs using RFC 2606 reserved domains. Should be selected normally and opened in new tabs.

  • http://example.com Standard HTTP URL
  • https://example.org Standard HTTPS URL
  • https://example.net/test/page HTTPS URL with Path

Case 2: Path Variations (Relative, Root-relative, Protocol-relative)

RELATIVE Expect: Resolved to Absolute & Opened

Relative and protocol-relative links. The browser's DOM resolves these to canonical absolute URLs prior to Linkclump tab dispatch.

  • ./subpages/dummy-target.html Relative path (opens local dummy target)
  • ../index.html Parent relative path (opens test page index)
  • //example.com/protocol-relative-test Protocol-relative URL (inherits scheme)

Case 3: Local & Sandboxed Files (file://, data:, blob:)

FILE DATA BLOB Expect: Selected (Browser Security Applies)

Local files and in-memory resources. Top-level navigation to data: URLs is blocked by modern browser security standards. blob: opens in-memory content within the same origin.

  • subpages/dummy-target.html (Local Target) Local navigation target
  • data:text/plain;charset=utf-8,Linkclump%20Plus%20Data%20URI%20Test%20Data Plain text data URI (Safe)
  • (Initializing Blob URL...) Dynamically created text Blob URL

Case 4: Script & Anchor Protocols (javascript:, #, Empty href)

JAVASCRIPT HASH Expect: Filtered Out (Never Selected)

These links must be completely excluded by Linkclump Plus during selection. Dragging across this entire area should result in 0 selected links and no bounding highlight on these items.

  • javascript:void(0) Explicitly rejected by regex /^javascript:/i
  • javascript:console.log('Linkclump-test') Explicitly rejected by regex /^javascript:/i
  • # (Empty hash fragment) Rejected by attribute check href === "#"
  • (Empty href attribute) Rejected by attribute check !rawLink.getAttribute("href")

Case 5: External Application Schemes (mailto:)

MAILTO Expect: Selected (OS App Hand-off)
Adversarial Safety Warning: Opening many mailto: links in new tabs will cause the operating system to launch multiple external mail client instances, potentially overwhelming system resources.
  • Link count on this page is strictly limited to 2 items.
  • It is strongly recommended to test these links using the "Copied to Clipboard" action instead of "Opened as New Tabs".
  • You can toggle the click interceptor below to safely test manual clicks without launching your mail client.

  • mailto:test-recipient-1@example.com Standard mailto scheme
  • mailto:test-recipient-2@example.org?subject=Linkclump%20Test... Mailto scheme with query parameters

Case 6: Browser Internal & Privileged Schemes (about:, chrome://)

ABOUT CHROME Expect: Selected → API Security Rejection (Safe)

Links pointing to browser-internal or privileged pages. While all these links are selected, counted, copied, and bookmarked normally on both browsers, their behavior under "Opened as New Tabs" differs significantly due to underlying browser API policies:

  • Chrome: Allows tabs.create to open chrome:// pages. For unknown about: schemes (such as Firefox's about:preferences), Chrome opens the tab but fails navigation with "このサイトにアクセスできません".
  • Firefox: Strictly restricts tabs.create at the API level (rejects chrome:// and privileged about: URLs with Illegal URL). Linkclump Plus's safeAsync catches this rejection, preventing tab creation while keeping the extension stable.
  • about:blank Chrome: Opens blank page / Firefox: Opens blank page
  • chrome://settings/ Chrome: Opens Settings / Firefox: Tab not opened (API rejection)
  • chrome://extensions/ Chrome: Opens Extensions / Firefox: Tab not opened (API rejection)
  • about:preferences Chrome: Scheme error page / Firefox: Tab not opened (API rejection)
  • about:addons Chrome: Scheme error page / Firefox: Tab not opened (API rejection)
  • about:config Chrome: Scheme error page / Firefox: Tab not opened (API rejection)

Case 7: Deprecated Protocols (ftp://)

FTP Expect: Selected → Deprecated Scheme Handling

FTP protocol support was removed from modern Chromium and Firefox releases. Linkclump Plus selects the link, but the browser will report a scheme error or attempt external protocol resolution.

  • ftp://example.com/test-file.txt Deprecated FTP URL
