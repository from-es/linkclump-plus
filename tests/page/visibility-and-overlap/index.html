About

This page verifies Linkclump Plus's behavior with hidden and overlapping elements, comparing browser layout reality with Linkclump Plus's hit-testing specifications.

Specification & Security Background:
  • Current Filter Rule: To maximize scanning performance across heavy pages, Linkclump Plus checks only display: none and visibility: hidden on candidate links.
  • Opacity & Overlays: Elements styled with opacity: 0 or occluded beneath opaque/semi-transparent layers (z-index overlays) are detected and selected if their geometric bounding box intersects the drag area.
  • Roadmap Consideration: Filtering transparent links (opacity: 0) and zero-size elements to prevent accidental activation of invisible/deceptive clickjacking links is proposed as an optional feature for future major versions.

Procedure & Expected Results

  1. For each hidden-element test case below, drag-select over the target area.
  2. For the Overlapping Elements case, drag-select across the stacked boxes and overlay.
  3. Compare results with the specification behavior listed below:
Target Element State Filter Rule Expected Result (Current Specification)
display: none Filtered in start() Ignored: Link is completely excluded from hit-testing.
visibility: hidden Filtered in start() Ignored: Link is excluded even though it consumes layout space.
opacity: 0 Not filtered Selected: Transparent link is detected per its layout bounding box.
width: 0; height: 0; Zero-area bounds Ignored: Zero-dimension bounding box does not intersect selection box.
position: absolute; left: -9999px; Out of viewport Ignored: Link coordinates fall far outside the on-screen selection area.
Overlapping Elements & Overlay Bounding box only All Selected: Box A, B, and C are all detected regardless of z-index or overlay text.
